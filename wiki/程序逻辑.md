## 3. 数据模型

### 3.1 assets 表（资产主表）

```sql
CREATE TABLE assets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    asset_no TEXT UNIQUE,              -- 资产编号（格式 前缀-YYYYMMDD-NN）
    name TEXT NOT NULL,                -- 资产名称（必填）
    category TEXT NOT NULL DEFAULT 'IT设备',  -- 分类：IT设备/办公家具/生产设备
    subtype TEXT,                      -- 子类（如 服务器/交换机/笔记本）
    user TEXT,                         -- 使用人
    dept TEXT,                         -- 所属部门
    location TEXT,                     -- 存放位置
    status TEXT,                       -- 状态：使用中/在库/维修中/闲置/运行中/报废
    brand TEXT,                        -- 品牌
    model TEXT,                        -- 型号
    sn TEXT,                           -- 序列号
    color TEXT,                        -- 颜色
    storage TEXT,                      -- 存储大小
    memory TEXT,                       -- 内存大小
    contract_no TEXT,                  -- 合同号
    supplier TEXT,                     -- 供应商
    purchase_date TEXT,                -- 采购日期
    price REAL DEFAULT 0,             -- 原值（元）
    warranty_months INTEGER DEFAULT 0, -- 保修月数（保留字段，表单已移除）
    warranty_expire TEXT,              -- 保修到期日 YYYY-MM-DD
    note TEXT,                         -- 备注
    rack_id TEXT,                      -- 所在机柜编号（外键逻辑）
    u_start INTEGER,                   -- 起始 U 位
    u_height INTEGER,                  -- U 高
    is_network_device INTEGER DEFAULT 0, -- 是否网络设备（0/1）
    config TEXT,                       -- JSON 扩展字段（含 system_info）
    inventory_time TEXT,               -- 盘点时间
    created_at TEXT DEFAULT (datetime('now','localtime')),
    updated_at TEXT DEFAULT (datetime('now','localtime'))
);
```

**索引**
- `idx_assets_category` ON `assets(category)`
- `idx_assets_rack` ON `assets(rack_id)`

### 3.2 racks 表（机柜表）

```sql
CREATE TABLE racks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    rack_id TEXT UNIQUE NOT NULL,      -- 机柜编号（唯一，创建后不可改）
    name TEXT,                         -- 机柜名称
    location TEXT,                     -- 位置
    total_u INTEGER DEFAULT 42,       -- 总 U 数
    status TEXT,                       -- 状态：使用中/闲置/停用
    contract_no TEXT,
    supplier TEXT,
    purchase_date TEXT,
    price REAL DEFAULT 0,
    warranty_months INTEGER DEFAULT 0,
    warranty_expire TEXT,
    note TEXT
);
```

### 3.3 ports 表（端口表）

```sql
CREATE TABLE ports (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    asset_id INTEGER NOT NULL,         -- 所属资产 ID（ON DELETE CASCADE）
    port_num INTEGER NOT NULL,         -- 端口号
    name TEXT,                         -- 端口名称
    speed TEXT,                        -- 速率
    mac TEXT,                          -- MAC 地址
    ip TEXT,                           -- IP 地址
    remote_device TEXT,                -- 对端设备
    remote_port TEXT,                  -- 对端端口
    note TEXT,                         -- 备注
    status TEXT DEFAULT 'disconnected', -- 状态：connected/disconnected/disabled
    FOREIGN KEY (asset_id) REFERENCES assets(id) ON DELETE CASCADE
);
```

**索引**
- `idx_ports_asset` ON `ports(asset_id)`

### 3.4 meta 表（元数据）

```sql
CREATE TABLE meta (
    key TEXT PRIMARY KEY,
    value TEXT
);
```

预留结构，目前仅用于扩展（演示数据判定已改为「数据库文件是否存在」）。

## 4. 路由注册

### 4.1 路由前缀

所有路由注册在 `APIRouter(prefix="/api/cmdb")` 下。

### 4.2 注册顺序陷阱

FastAPI 按注册顺序匹配路由。以下固定路径**必须**注册在通配路由之前：

```python
# 正确顺序
router.post("/assets/batch-update", ...)    # ← 先注册
router.post("/assets/batch-delete", ...)    # ← 先注册
router.get("/assets/import-template", ...)  # ← 先注册
router.post("/assets/import-csv", ...)      # ← 先注册
router.get("/assets/{asset_id}", ...)       # ← 后注册（通配）
router.put("/assets/{asset_id}", ...)       # ← 后注册（通配）
router.delete("/assets/{asset_id}", ...)    # ← 后注册（通配）
```

若顺序颠倒，`/assets/batch-update` 会被 `/assets/{asset_id}` 截走，导致 404 或参数错乱。

## 5. 资产编号生成

### 5.1 格式

```
前缀-YYYYMMDD-NN
IT-20260826-00
├─┤ ├──────┤ ├┤
前缀  日期   序号
```

### 5.2 前缀对照

| 分类 | 前缀 |
| --- | --- |
| IT设备 | IT |
| 办公家具 | OF |
| 生产设备 | PE |
| 其他 | AS |

### 5.3 生成逻辑（`_gen_asset_no`）

1. 查询当日同前缀已用最大序号。
2. 取最大序号 +1，格式化为 2 位（如 `00`、`01`）。
3. 若序号超过 99，抛出 ValueError（避免溢出破坏格式）。
4. 支持传入 conn 参数复用外层事务连接。

### 5.4 校验逻辑（`validate_asset_no`）

1. 正则匹配：`^(IT|OF|PE|AS)-(\d{8})-(\d{2})$`
2. 日期有效性校验：`datetime.strptime(date, "%Y%m%d")`
3. 不通过抛 ValueError，由路由层转 400。

## 6. U 位校验机制

### 6.1 校验函数

`assets.py` → `_validate_u_position(conn, rack_id, u_start, u_height, exclude_id=None)`

### 6.2 校验规则

1. `u_start ≥ 1` 且 `u_height ≥ 1`。
2. `rack_id` 对应的机柜必须存在。
3. `u_start + u_height - 1 ≤ 机柜 total_u`（不超出机柜总 U 数）。
4. 占用区间 `[u_start, u_start+u_height-1]` 不得与同机柜其他资产重叠。
5. `exclude_id` 参数用于编辑时排除自身。

### 6.3 并发安全

- `create_asset` 和 `update_asset` 在校验前执行 `BEGIN IMMEDIATE`（立即取写锁）。
- 使「校验 → 写入」整体串行化，消除 TOCTOU 竞态。

## 7. 安全与审计

### 7.1 鉴权

所有接口通过 `Depends(get_current_user)` 鉴权，从请求头 `Authorization: Bearer <token>` 提取用户身份。

### 7.2 审计日志

所有写操作调用 `audit_log()`：

```python
audit_log("cmdb_asset_add", "新增资产: Dell R750 (IT-20230601-01)", "success", username=user)
```

审计操作类型：

| 操作类型 | 说明 |
| --- | --- |
| cmdb_asset_add | 新增资产 |
| cmdb_asset_update | 更新资产 |
| cmdb_asset_delete | 删除资产 |
| cmdb_asset_batch_inventory | 批量更新盘点时间 |
| cmdb_asset_batch_delete | 批量删除 |
| cmdb_asset_import | CSV 导入 |
| cmdb_asset_unbind | 资产移出机柜 |
| cmdb_rack_add | 新增机柜 |
| cmdb_rack_update | 更新机柜 |
| cmdb_rack_delete | 删除机柜 |
| cmdb_port_update | 更新端口 |
| cmdb_backup_export | 导出备份 |
| cmdb_backup_import | 导入备份 |

### 7.3 XSS 防护

- 用户可写内容（资产名、备注等）在拼入 HTML 报表前统一经 `html.escape()` 转义。
- 报表模板中 `{{_esc(value)}}` 确保无存储型 XSS。

### 7.4 CSV 公式注入防护

CSV 导出时，以 `= + - @ \t \r` 开头的字段自动加前缀 `'` 消毒，防止 Excel 公式注入。

### 7.5 LIKE 模式注入防护

搜索参数中的 `%` 和 `_` 通配符会被转义（`ESCAPE '\'`），防止 LIKE 模式注入。

## 11. 导入导出

### 11.1 CSV 导入

```
CSV 文本 → 去 BOM → 跳过 # 注释行和空行 → 解析表头 → 逐行校验 → create_asset()
```

- 表头必须包含 `name` 列。
- `asset_no` 留空自动生成。
- 子类命中 `NETWORK_SUBTYPES` 时自动标记为网络设备。
- 返回 `{added, failed, errors}`。

### 11.2 JSON 备份导出

```
SELECT racks → EXPORT_RACK_FIELDS 字段筛选
SELECT assets → EXPORT_ASSET_FIELDS 字段筛选 + ports 关联查询
→ 组装 {meta, racks, assets} → JSON
```

### 11.3 JSON 备份导入

**merge 模式**
```
遍历 racks → _upsert_rack (按 rack_id 匹配)
遍历 assets → 按 asset_no 匹配 → 有则 _update_asset_full / 无则 _insert_asset_full
```

**overwrite 模式**
```
DELETE FROM ports → DELETE FROM assets → DELETE FROM racks → 逐条插入
```

## 12. 并发控制

### 12.1 数据库连接

- SQLite 连接使用 `PRAGMA busy_timeout=5000`（5 秒超时）。
- 使用 WAL 日志模式（`PRAGMA journal_mode=WAL`），支持并发读。
- 开启外键约束（`PRAGMA foreign_keys=ON`）。

### 12.2 写事务

- `create_asset` / `update_asset` / `batch_delete_assets` / `batch_update_inventory_time` 均使用 `BEGIN IMMEDIATE`。
- `BEGIN IMMEDIATE` 立即获取写锁，使「校验 → 写入」串行化，避免 TOCTOU 竞态。

## 13. 数据库迁移

### 13.1 自动迁移

`init_db()` 中包含多个 `ALTER TABLE ADD COLUMN` 迁移：

| 目标表 | 新增列 | 版本 |
| --- | --- | --- |
| assets | inventory_time | 早期版本 |
| assets | color, storage, memory | 中期版本 |
| ports | mac, ip | 中期版本 |

### 13.2 密码字段清理

启动时自动清理存量资产 `config.system_info` 中的 `password` 密文字段（安全需求：CMDB 不再保存密码）。
