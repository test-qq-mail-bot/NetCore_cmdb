# 插件制作过程（以 cmdb 为例）

本文以 cmdb 插件为样板，说明「业务数据型插件」的开发要点，可复用到其他插件。

## 1. 目录约定

```
plugins/cmdb/
├── plugin.py          # 入口：集中定义 /api/cmdb 路由与菜单
├── config.yaml        # 插件默认配置
├── db.py              # SQLite 连接
├── common.py          # 建库、种子数据、公共工具
├── modules/           # 业务模块（按职责拆分）
├── frontend/          # 前端页面脚本
└── data/              # 运行时 SQLite（不进仓库）
```

> 路由可以在 `plugin.py` 内集中定义（cmdb 采用此方式，简单直观），也可拆分到 `routes/` 包（netconfig_guardian / ops_toolbox 采用，适合接口多的插件）。

## 2. 继承 BasePlugin

```python
from fastapi import APIRouter, Depends
from core.auth import get_current_user
from plugins.base_plugin import BasePlugin

class CMDBPlugin(BasePlugin):
    def get_metadata(self): return {"name":"cmdb","version":"20260824-V2",...}
    def on_load(self):
        from plugins.cmdb import common
        common.init_db()
        return True
    def get_routes(self):
        router = APIRouter(prefix="/api/cmdb")
        # ... 注册接口
        return router
    def get_menus(self): return [ ... ]   # 左侧菜单结构
```

## 3. 路由注册顺序陷阱

`/api/cmdb/assets/batch-update` 等固定路径必须早于 `/api/cmdb/assets/{asset_id}` 注册。FastAPI 按注册顺序匹配，固定路径放后面会被 `{asset_id}` 通配截走，导致「批量接口 404 / 参数错乱」。

## 4. 数据访问

- 用 `core.config_loader.PLUGINS_DIR / "cmdb" / "data" / "cmdb.db"` 定位数据库，保证开发/打包路径一致。
- 建表与种子在 `common.init_db()` 中 `CREATE TABLE IF NOT EXISTS` + 首次 `seed_if_empty`。

## 5. 鉴权与审计

- 每个接口加 `user: str = Depends(get_current_user)`。
- 写操作调用 `audit_log("cmdb_asset_add", "新增资产: %s" % name, "success", username=user)`。

## 6. 前端自注册

`frontend/cmdb_it.js` 等通过 `window.NC.registerPage(id, {template,data,methods}, title, path)` 注册页面；路径与 `get_menus()` 中的 `path` 对应。前端清单由框架 `/api/plugins/frontend-manifest` 自动收集。

## 7. 依赖与交付

- `requirements.txt` 仅列本插件依赖（cmdb 仅 `fastapi==0.141.1`），全部 `==` 锁定。
- 仓库只放源码，`data/`、缓存、二进制不进仓库（`.gitignore` 排除）。
- 用户下载后整体放入 `plugins/cmdb/` 即被识别。

## 8. 可复用经验

- 报表统一 `_build_report_html()` + CSV BOM，避免中文乱码。
- 用户可写内容（资产名、备注）一律 HTML 转义，防 XSS。
- 危险操作（删机柜）默认拒绝 + `force` 兜底，且「解绑不删台账」保护数据。
- 批量接口与单条接口分开注册，避免路由冲突。
